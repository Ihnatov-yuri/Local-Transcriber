# Transcriber for Android: catch-up plan, September 2026

Status: proposed, awaiting go. Written 2026-09-11.
Owner: Yuri Ihnatov. Scope: bring the Android app to parity with the Mac app
(Transcriberr v3.2.6) and onto the 2026 on-device stack.

Everything in this document was checked against primary sources on
2026-09-11 (release pages, model cards, Android developer docs). Links are in
the Sources section at the end. Items marked *unverified* were reported but
not confirmed first-hand.

transcripts, folders and tags, dictation.

## 2. What the research changed

**Runtime.** The app is about 50 releases behind sherpa-onnx. k2-fsa now
publishes an official Android AAR on each GitHub release (v1.13.8 on
2026-09-10, bundling ONNX Runtime 1.28.2, 16 KB aligned). The third-party
mirror is no longer needed. The Kotlin result class still has no per-token
confidence; the C++ side has `ys_log_probs` for transducers and the JNI
exposure is an open PR (#3638).

**Live transcription.** NVIDIA Nemotron 3.5 ASR streaming 0.6B (2026-06-11,
sherpa-onnx v1.13.3+) is a cache-aware streaming transducer covering Arabic,
Ukrainian, Dutch and English in its top tier, about 475 MB int8. It replaces
the 5-second Gemma chunk loop on the Record screen and is the right engine
for dictation.

**Arabic.** Nothing on-device is Gulf-dialect tuned. Meta Omnilingual ASR CTC
300M (292 MB int8, in sherpa-onnx) has a dedicated Gulf Arabic code (`afb`)
and gives timestamps. Cohere Transcribe Arabic (2026-07-07) leads the open
Arabic leaderboard but has no sherpa-onnx export and no timestamps. Qwen3-ASR
0.6B covers Arabic and Dutch but not Ukrainian, has no timestamps, and is
about 2 GB. Gemma 4 stays a voice for Arabic; Super mode for Arabic pairs
Gemma with Omnilingual.

**English, Dutch, Ukrainian.** Parakeet TDT 0.6B v3 remains the best
size/accuracy/timestamp combination (FLEURS WER nl 7.5, uk 6.8). No v4
exists. Not Arabic.

**Gemma and LiteRT-LM.** Latest is 0.17.0 (2026-09-09). The silent-wedge
issue (#2202) is still open with new reports in August (#3266). Two things
landed since 0.11.0 that we should use: `Conversation.cancelProcess()` and
constrained decoding (`ResponseFormat.json(schema)` / `.regex()` with
`enableResponseFormat = true`). Gemma 4 has no smaller audio variant; a
silent weight refresh in July 2026 is reported but *unverified*. Gemini Nano
via ML Kit GenAI does not list the Galaxy S24 Ultra, so it is not an option.

**Fusion.** ROVER-style word voting is still the reliable method (2026
Whisper + Canary + Parakeet ensemble: 6.3 to 3.9 WER, *snippet only*).
Free-form LLM correction makes transcripts worse in several 2025 studies
(one cascaded 7B correction raised WER from 17.7 to 31.3). What works: lock
the spans both engines agree on, present only the disputed spans as choices,
pass confidence where available, forbid new content, and constrain the
output format. That is ClozeGER plus confidence-guided prompting, and it maps
directly onto LiteRT-LM's constrained decoding.

**Diarization.** Independent clustering per 5-minute window multiplies
speakers; pyannote community-1 (2025-09-29) and DiariZen both cluster
globally with VBx. sherpa-onnx v1.13.8 adds per-segment confidence and a
configurable window shift, but clustering is still complete-linkage
agglomerative with `threshold` and `num_clusters` as the only levers. Best
evidence for non-English speakers: WeSpeaker SimAM-ResNet34 trained on
VoxBlink2 (won the 2026 TidyVoice cross-lingual challenge, 2.97 to 2.18 EER
with language-subspace removal). Loading it through sherpa-onnx's WeSpeaker
path is *untested*. Sortformer is English-trained, 4-speaker capped, 492 MB
fp32, not a fit. LLM refinement that takes cluster IDs plus confidence and
returns a merge map cut DER from 23 to 16 in a 2026 study.

**Android platform.** Android 17 (API 37) is current. targetSdk 36 makes
edge-to-edge and predictive back mandatory. targetSdk 37 makes
`System.load()` of writable native files throw (we only use
`loadLibrary`, so no impact). Foreground service caps: `mediaProcessing` and
`dataSync` 6 h per day; `microphone` and `specialUse` have no cap, and a
sideloaded app needs no Play declaration for `specialUse`. Android 16 counts
jobs launched from a foreground service against the JobScheduler quota, so
long jobs must start the service directly, which we already do. Android 17
introduces a memory limiter that counts native memory per process; a
foreground service counts as not visible (roughly 4 GiB on a 12 GB device),
and `largeHeap` does not help native allocations. 16 KB pages: all
dependencies are aligned once upgraded; whisper.cpp needs NDK r28 or newer.

**Distribution.** Google's developer verification for sideloading reaches the
Netherlands in 2027 at the earliest; adb installs stay exempt; a free limited
distribution account (package name + signing cert, no ID) covers up to 20
devices. Obtainium reads GitHub Releases if the APK name is stable and
versionCode is monotonic.

**Dictation on Android.** Wispr Flow launched an Android app on 2026-02-23:
floating bubble over the keyboard, AccessibilityService for insertion,
clipboard fallback, cloud only. Since API 33 an accessibility service that
declares the IME capability gets `AccessibilityInputConnection` with
`commitText` and `getSurroundingText`, and `AccessibilityNodeInfo` exposes the
focused field's text, selection, password flag and package. Android 16 hides
views marked accessibility-sensitive from non-tool services. Open-source
on-device precedents: FUTO Voice Input (IME, whisper.cpp), Transcribro,
phone-whisper (sherpa-onnx Parakeet, overlay + accessibility).

## 3. Engine matrix after this plan

| Languages selected | Default engine | Super mode pair | Live / dictation |
|---|---|---|---|
| English, Dutch, Ukrainian (any mix) | Parakeet TDT 0.6B v3 | Parakeet + Whisper large-v3-turbo, Gemma arbitrates | Nemotron 3.5 streaming |
| Arabic (Gulf) | Gemma 4 audio | Gemma + Omnilingual CTC 300M (`afb`), arbitration off when Gemma is one of the voices | Nemotron 3.5 streaming |
| Arabic + European mix | Omnilingual CTC 300M | Omnilingual + Gemma | Nemotron 3.5 streaming |
| Auto / empty | Omnilingual CTC 300M | Omnilingual + Whisper | Nemotron 3.5 streaming |

Gemma 4 handles all text work (presets, titles, arbitration, speaker merge
map). Whisper stays available as an explicit choice. Vote priors per
language: Whisper anchors Ukrainian, Parakeet anchors English and Dutch,
Omnilingual anchors Arabic.

## 4. Phases

Effort is working days for one person with the phone available for the
on-device steps. Every phase ends with a green build, its unit tests, and a
commit on `main`. Versions bump per shipped build (see section 6).

### Phase 0: Foundation (1 day)

Goal: current toolchain and runtime, no behaviour change beyond what the
platform forces.

- [ ] `git checkout main && git pull` (local main is 4 commits behind; HEAD is the merged feature branch).
- [ ] AGP 9.4.0, Gradle 9.7.1, Kotlin 2.4.20 (remove the standalone `kotlin-android` plugin; AGP 9 has built-in Kotlin), KSP 2.3.12.
- [ ] compileSdk and targetSdk 37; Compose BOM 2026.09.00 (requires compileSdk 37); Material 3 1.4.0; Room 2.8.5; Media3 1.11.1; coroutines 1.11.0; serialization 1.11.0; DataStore 1.2.1.
- [ ] Edge-to-edge and predictive back: audit every screen; replace any `onBackPressed` use.
- [ ] NDK r30 LTS; whisper.cpp v1.9.4 via `scripts/fetch-whisper-cpp.sh` (pin the tag); keep `-DANDROID_SUPPORT_FLEXIBLE_PAGE_SIZES=ON`; verify 16 KB alignment of every `.so` in the APK with `llvm-readelf -l`.
- [ ] Replace `com.bihe0832.android:lib-sherpa-onnx` + `onnxruntime-android` pin with the official `sherpa-onnx-1.13.8.aar` (50 MB, vendored under `app/libs/` or fetched by script). Drop the vendored `OfflineSpeakerDiarization.kt` if the AAR now ships it; otherwise refresh it from the v1.13.8 source.
- [ ] LiteRT-LM 0.17.0. Diff the Kotlin API against 0.11.0; adopt `cancelProcess()` in the watchdog path; enable `enableResponseFormat` on the conversations used for JSON outputs.
- [ ] TranscriptionService: foreground type `specialUse` (no 6 h cap) with a `mediaProcessing` fallback and an `onTimeout` handler that checkpoints the queue. RecordingService stays `microphone`.
- [ ] Memory: read `ActivityManager.getMemoryInfo` and the Android 17 limiter status at job start; refuse Gemma E4B when the limit is below 5 GiB and say why.
- [ ] Versioning: `versionName = "1.0.0"`, `versionCode = 100`; release `signingConfig` reading `~/.android/transcriber.jks` via `local.properties` keys; v2 + v3 signing.
- [ ] `scripts/release.sh`: assembleRelease, verify alignment, rename to `transcriber-<version>-arm64.apk`, `gh release create v<version>` with notes.
- [ ] README and NEXT_STEPS refresh: remove the dead `../Transcriber/android-plan` pointer, mark chunked diarization as shipped, point at this plan.
- [ ] Reword the "Russian doll" comment in SettingsScreen.kt (project rule: no mentions).

Acceptance: debug and release builds green on the new toolchain; app installs and records on the S24 Ultra; existing recordings and Room data survive the update (Room schema unchanged in this phase).

### Phase 1: Diarization done properly (2 days)

Goal: one speaker per real speaker on the Arabic two-person recording, and
word-level attribution for every engine.

- [ ] Global clustering: collect embeddings and their time spans per 5-minute window, then run one agglomerative pass over the whole file. Keep the window loop for memory; drop the per-window cluster stitching.
- [ ] Bind `Expected speakers` from the RUN sheet to `num_clusters` when set; expose `threshold` in Settings (default 0.5 English, 0.7 otherwise); expose `min_duration_on/off`.
- [ ] Catalog: add WeSpeaker SimAM-ResNet34 VoxBlink2 (WeSpeaker pretrained list) as "multilingual, recommended for non-English". Verify it loads through the WeSpeaker model path; if not, keep WeSpeaker ResNet221-LM as default and note the failure.
- [ ] Use sherpa-onnx's new per-segment confidence (v1.13.8) and pass it downstream.
- [ ] Over-segmentation warning: when clusters exceed 6 and expected speakers is unset, surface a one-tap "set expected speakers" hint in the stage event.
- [ ] Word-level attribution (WhisperX rule): per word, dominant overlap speaker; unassigned words take the nearest segment by midpoint. Works from Parakeet/Nemotron/Omnilingual timestamps and whisper.cpp token timestamps.
- [ ] Turn coalescing with a tunable gap (Settings, default from the Mac app), then renumber speakers by first appearance.
- [ ] Speaker-name inference from the conversation (port the Mac regex set for English, Dutch, Ukrainian; add Arabic patterns for "my name is" and "this is").
- [ ] Gemma merge map: optional pass that receives cluster IDs, durations and confidences, returns `{merge: [[a,b],...]}` under a JSON schema via constrained decoding. Applied only when it merges, never splits.
- [ ] Unit tests: clustering merge across windows on synthetic embeddings, attribution rules, coalescing, name inference, merge-map application.

Acceptance: the 30-minute Gulf Arabic recording yields 2 speakers with expected speakers unset (or with it set to 2), hybrid conflicts drop below 10 percent; English meeting attribution matches the Mac app on the same file.

### Phase 2: Engines (2 days)

Goal: Parakeet, Omnilingual and Nemotron wired through the existing `AsrBackend` seam.

- [ ] `AsrBackendKind`: add `Parakeet`, `Omnilingual`, `NemotronStream`. `AsrFactory` model resolution per kind (directories, not single files: encoder/decoder/joiner + tokens).
- [ ] `SherpaOfflineBackend` (Parakeet transducer and Omnilingual CTC through `OfflineRecognizer`): returns word segments with timestamps; VAD-aligned chunks using the existing `scanSilences` / `computeCutPoints`, chunk length 30 to 60 s, no overlap needed at silence cuts.
- [ ] `RawSegment` gains optional `words: List<Word(start, end, text, confidence?)>`; JNI constructor for whisper.cpp keeps the 3-arg shape.
- [ ] Catalog entries with sizes: Parakeet TDT 0.6B v3 int8 (487 MB), Omnilingual 300M CTC int8 (292 MB), Nemotron 3.5 streaming 0.6B 560 ms int8 (475 MB). Downloader learns tar.bz2 extraction with a `.partial` marker.
- [ ] Engine policy in the RUN sheet: "Auto" picks by the language set (section 3); explicit picks remain.
- [ ] Nemotron `OnlineRecognizer` for the Record screen: feed 16 kHz frames from `WavRecorder`, endpointing on, emit partial and final segments; delete the 5-second Gemma chunk loop; keep Gemma live as an explicit fallback for a release, then remove.
- [ ] Confidence: whisper.cpp exposes `whisper_full_get_token_p`; add it to the JNI shim and aggregate per word (geometric mean). For sherpa transducers, track PR #3638; if it merges, adopt; if not, build the AAR once with that patch and note it in the README.
- [ ] Speed check on the S24 Ultra: real-time factor for each engine on a 10-minute file, recorded in the README.

Acceptance: a Dutch meeting transcribes with Parakeet at or above 5x real time on CPU with word timestamps; the Arabic recording transcribes with Omnilingual; live transcription shows partials under one second behind speech.

### Phase 3: Super mode (2 days)

Goal: the Mac's ensemble, adapted to phone constraints and 2026 findings.

- [ ] `EnsembleBackend`: two engines per chunk, sequential on the phone (no ANE/GPU split), per-engine wedge recovery, Gemma benched after two wedges per run.
- [ ] ROVER word alignment on timestamps, vote with agreement plus per-language priors; whisper token probabilities used when present; Dice similarity to score disputes; `ChunkConfidence` text sanity (repetition loop, length vs duration) ported as is.
- [ ] Arbitration, second pass, bounded to the worst N disputes: prompt with agreed spans locked, disputed spans as numbered choices, output constrained to `{choices: [int]}` via `ResponseFormat.json`. No free text, so the model cannot add content.
- [ ] RUN sheet: Super toggle, pair picker, "max quality" (arbitration) toggle, same names as the Mac.
- [ ] Unit tests: alignment, vote, dispute extraction, choice application, bench logic.

Acceptance: on the Ukrainian meeting used for the Mac sweep, Super (Whisper + Parakeet) reads at least as well as Whisper alone and never worse; on the Arabic recording, Gemma + Omnilingual reduces Gemma's hallucinated spans (count them by hand on a 5-minute sample).

### Phase 4: Text pipeline and versions (2 days)

- [ ] Port `TextDestutter` (109 lines): stutters, phrase echoes, hesitation fillers; runs before every preset and on segment display when "Remove fillers" is on.
- [ ] Minutes preset (decisions and action items by owner), same prompt as the Mac.
- [ ] Per-language vocabulary: global plus per-language lists, injected by the selected languages into ASR prompts (Gemma), whisper.cpp initial prompt, and every preset.
- [ ] Learned names: harvest recurring capitalised terms from the library at launch; offer unknown names after each run as one-tap vocabulary additions (Settings, "Learned").
- [ ] Versioned transcripts: Room migration 3 to 4 adding `transcript_versions` (engineId, engineLabel, createdAt, segmentCount, segmentsJSON); snapshot before every run; Detail screen version picker with compare and restore; rescue snapshot on any wipe path.
- [ ] Auto-title and auto-classify (Meeting / Interview / Note / Idea) in one constrained JSON call.
- [ ] Unit tests: destutter cases from the Mac suite, vocabulary selection, version snapshot and restore, harvester.

Acceptance: re-running a recording with another engine never loses the previous text; the Minutes output on a real meeting lists owners.

### Phase 5: Backlog, tests, release (1 to 2 days)

- [ ] Whisper long files: chunk at VAD cut points and stitch with offsets (removes the OOM on multi-hour audio).
- [ ] Library rows show job state (Queued, Transcribing 4/12, Waiting for charger).
- [ ] `Stopping` state in `LiveStatus` and `JobStatus`.
- [ ] Real Markdown renderer (tables, fenced code, blockquotes) via commonmark; share as `text/markdown`.
- [ ] Robolectric 4.17 for Room DAO and repository tests; JVM tests for search escaping, cut points, boundary dedup.
- [ ] Release 1.0.0: tag, signed APK, notes with what changed, how, and what was learned.

### Phase 6 (optional): Folders, tags, knowledge base (1 day)

- [ ] Room entities Folder and Tag with join table; Library filter chips; move-to-folder and tag sheets, mirroring the Mac UI.
- [ ] Export the library as the same JSON the Mac KB CLI reads, so sidecars and metadata round-trip.

### Phase 7 (optional): Dictation (3 days)

- [ ] Engine: Nemotron streaming for partials, Parakeet or Omnilingual final pass on release (same two-stage shape as the Mac).
- [ ] Insertion: AccessibilityService declaring the IME capability, `AccessibilityInputConnection.commitText`; clipboard fallback; never active in password fields or accessibility-sensitive views.
- [ ] Trigger: floating bubble (hold to talk, tap to toggle) and a volume-key long-press option; an IME "voice" subtype as the reliable path for keyboards that bind to it.
- [ ] Context: focused field text and selection via `getSurroundingText`, app package for per-app rules (verbatim for terminals, clean by default, smart for chat and mail), same deterministic command set as the Mac ("new paragraph", "scratch that" in English, Dutch, Ukrainian).
- [ ] History: each passage saved as a recording in a Dictation folder (needs phase 6).

## 5. Risks and how they are handled

| Risk | Mitigation |
|---|---|
| sherpa-onnx JNI still lacks transducer confidence | Agreement + priors vote works without it; whisper token probabilities cover the Whisper pairings; patch build as last resort |
| Gemma wedges persist on 0.17.0 | Watchdog + `cancelProcess()` + bench after two wedges; Gemma is never the only voice in Super |
| VoxBlink2 embedding fails to load in sherpa-onnx | Keep WeSpeaker ResNet221-LM; document |
| Android 17 memory limiter kills the job process | Pre-flight memory check; prefer E2B; stream audio; never hold the full float buffer for sherpa (windows already bounded) |
| Parakeet real-time factor on phone unknown (no published numbers) | Measure in phase 2 before making it the default; Omnilingual 300M is the fallback |
| Toolchain jump (AGP 9.4, Kotlin 2.4, compileSdk 37) breaks the build | Phase 0 is isolated and committed alone; each bump separately |
| No phone attached during development | JVM and Robolectric tests for every pure-logic piece; emulator arm64 image for UI; on-device phases scheduled when the phone is available |

## 6. Release procedure (every shipped build)

1. Bump `versionName` and `versionCode` in `app/build.gradle.kts`.
2. `./gradlew test` green.
3. `scripts/release.sh` (assembleRelease, alignment check, rename, `gh release create`).
4. Release notes: what changed, how it was fixed, what was learned.
5. Push `main` and the tag. No Co-Authored-By trailers.
